개발 공부를 시작하고 나서 한동안은 영상 강의와 블로그 글로만 공부했어요. 짧고 빠르게 필요한 것만 찾을 수 있으니까요. 그런데 어느 순간부터 지식이 조각조각 흩어져 있다는 느낌이 들었어요. 그래서 올해는 마음먹고 개발 서적을 읽기 시작했고, 지금까지 다섯 권을 끝냈어요. 오늘은 그 다섯 권을 읽으면서 느낀 점을 솔직하게 적어 보려고 해요.

책 제목을 그대로 적기보다는 어떤 종류의 책이었는지, 무엇을 배웠는지 위주로 이야기할게요. 비슷한 책은 서점에 많으니 고를 때 참고가 되면 좋겠어요.

## 책을 고른 기준

### 처음이라 욕심부리지 않기

처음엔 유명하다는 두꺼운 책부터 샀다가 앞부분 서른 쪽에서 멈췄어요. 그 뒤로는 기준을 바꿨어요.

- 지금 하고 있는 일과 바로 연결되는 책
- 한 달 안에 끝낼 수 있는 분량
- 예제를 직접 따라 해 볼 수 있는 책
- 서점에서 첫 장을 읽었을 때 문장이 편하게 읽히는 책

> 좋은 책보다 끝까지 읽을 수 있는 책이 먼저라는 걸 첫 실패에서 배웠어요.

## 다섯 권 이야기

### 첫 번째: 읽기 좋은 코드에 관한 책

이름 짓기, 함수 나누기, 주석 다는 법 같은 이야기를 다룬 책이었어요. 내용 자체는 어렵지 않은데, 읽고 나서 제 코드를 다시 보니 고칠 게 너무 많아서 웃음이 나왔어요. 특히 "함수는 한 가지 일만 해야 한다"는 말을 읽고 나서, 백 줄 넘던 함수를 다섯 개로 나눴던 기억이 나요.

아래는 책을 읽고 나서 실제로 고쳐 본 코드예요.

```javascript
// 고치기 전
function handle(u) {
  if (u.a && u.e.includes('@') && u.p.length >= 8) {
    save(u);
  }
}

// 고친 후
function isValidUser(user) {
  return user.agreed && user.email.includes('@') && user.password.length >= 8;
}

function registerUser(user) {
  if (isValidUser(user)) {
    save(user);
  }
}
```

이름만 바꿨을 뿐인데 다음 날 다시 읽었을 때 훨씬 이해하기 쉬웠어요.

### 두 번째: 테스트 작성에 관한 책

테스트를 먼저 쓰고 코드를 나중에 쓰는 방식을 소개한 책이에요. 처음엔 순서가 거꾸로라서 불편했는데, 따라 하다 보니 무엇을 만들어야 하는지가 먼저 분명해지는 경험을 했어요. 지금은 모든 코드에 적용하진 못하지만, 계산이 복잡한 부분만큼은 테스트부터 써요.

### 세 번째: 네트워크 기초에 관한 책

브라우저에 주소를 입력하면 무슨 일이 일어나는지 처음부터 끝까지 설명해 주는 책이었어요. 그림이 많아서 비전공자인 저도 따라가기 쉬웠어요. 이 책을 읽고 나서 동료가 말하는 "요청이 어디서 막혔는지 보자"는 말을 처음으로 제대로 이해하게 됐어요.

### 네 번째: 데이터베이스 설계에 관한 책

솔직히 다섯 권 중에 제일 어려웠어요. 정규화 부분에서 몇 번이나 다시 읽었어요. 그래도 이 책 덕분에 테이블을 만들 때 "이 정보가 두 군데 들어가 있지 않나" 하고 한 번 더 생각하게 됐어요. 예전에 만든 프로젝트의 테이블을 다시 그려 보는 연습이 특히 도움이 됐어요.

### 다섯 번째: 개발자의 일하는 방식에 관한 책

마지막은 기술보다는 태도에 관한 책이었어요. 일정을 어떻게 이야기할지, 모르는 걸 어떻게 물어볼지, 실수했을 때 어떻게 공유할지 같은 내용이요. 가볍게 읽을 수 있었는데, 오히려 가장 자주 떠올리는 책이 됐어요.

## 다섯 권 한눈에 보기

| 분야 | 난이도 | 읽은 기간 | 다시 읽고 싶은 정도 |
| --- | --- | --- | --- |
| 읽기 좋은 코드 | 쉬움 | 2주 | 매우 높음 |
| 테스트 작성 | 보통 | 3주 | 높음 |
| 네트워크 기초 | 쉬움 | 2주 | 보통 |
| 데이터베이스 설계 | 어려움 | 5주 | 높음 |
| 일하는 방식 | 쉬움 | 1주 | 매우 높음 |

## 책을 끝까지 읽기 위해 한 일

### 나만의 독서 루틴

1. 출근 전 이십 분, 딱 한 챕터만 읽기
2. 읽은 챕터는 세 줄로 요약해서 메모장에 남기기
3. 예제가 있으면 주말에 몰아서 직접 쳐 보기
4. 한 권을 끝내면 다음 책은 일주일 쉬고 시작하기

### 메모는 이렇게 남겼어요

```text
[책] 읽기 좋은 코드 - 3장
- 변수 이름에 단위를 넣자 (timeoutMs, sizeKb)
- 부정형 이름은 헷갈린다 (isNotEmpty 대신 hasItems)
- 내일 할 일: 프로젝트 설정 파일 이름 점검
```

마지막 줄에 "내일 할 일"을 적어 두니까 읽은 내용이 실제 일로 이어졌어요.

## 마치며

책 다섯 권을 읽었다고 실력이 갑자기 늘지는 않았어요. 그래도 흩어져 있던 조각들이 조금씩 이어지는 느낌은 분명히 받았어요. 블로그 글이 필요한 답을 빠르게 알려 준다면, 책은 그 답이 왜 그런지를 차분히 설명해 주는 것 같아요.

혹시 개발 서적을 처음 읽어 보려고 한다면, 얇고 쉬운 책 한 권으로 시작해 보세요. 한 권을 끝내는 경험이 다음 책을 펼치게 하는 가장 큰 힘이 되더라고요. 저는 다음으로 운영체제 기초에 관한 책을 골라 두었어요. 다 읽으면 또 후기 남길게요.
