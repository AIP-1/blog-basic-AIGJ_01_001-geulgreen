이번 미션 주제는 "오늘 배운 한 가지를 정리하기"였어요. 마침 오늘 스터디에서 웹 접근성에 대해 배웠는데, 생각보다 충격을 많이 받아서 이걸 주제로 골랐어요. 제가 지금까지 만든 화면들이 누군가에게는 아예 쓸 수 없는 화면이었을 수도 있다는 걸 알게 됐거든요.

## 접근성이 뭔지부터

### 모두가 같은 방법으로 웹을 쓰지는 않아요

웹 접근성은 장애가 있든 없든, 어떤 환경에 있든 누구나 웹을 이용할 수 있게 만드는 거예요. 화면을 눈으로 보지 못해서 화면 낭독기로 듣는 사람도 있고, 마우스를 쓰기 어려워서 키보드만으로 이동하는 사람도 있어요. 손을 다쳐서 잠깐 한 손으로만 휴대폰을 쓰는 사람, 햇빛이 강한 곳에서 화면을 보는 사람도 비슷한 어려움을 겪어요.

스터디에서 강사님이 화면 낭독기를 켜고 제가 만든 연습용 페이지를 보여 주셨는데, 버튼마다 "버튼"이라고만 읽혀서 무엇을 누르는 건지 전혀 알 수 없었어요. 정말 부끄러웠어요.

> 접근성은 특별한 누군가를 위한 기능이 아니라, 언젠가의 나를 위한 배려예요.

## 오늘 배운 기본 원칙

### 의미에 맞는 태그 쓰기

가장 먼저 배운 건 의미에 맞는 요소를 쓰는 거예요. 클릭할 수 있는 건 버튼으로, 다른 곳으로 이동하는 건 링크로, 제목은 제목 요소로 만들어야 해요. 아무 요소에나 클릭 이벤트를 붙이면 눈으로 볼 땐 똑같아 보여도, 키보드나 화면 낭독기로는 존재조차 알 수 없게 돼요.

### 대체 텍스트 붙이기

이미지에는 그 이미지가 무엇을 전달하는지 설명하는 대체 텍스트를 붙여야 해요. 장식용 이미지라면 오히려 빈 값으로 두어서 화면 낭독기가 건너뛰게 하는 게 좋대요. 모든 이미지에 "이미지"라고 적는 건 아무 도움이 안 된다는 것도 배웠어요.

### 키보드로만 써 보기

오늘 숙제로 받은 게 "마우스 없이 내가 만든 사이트 써 보기"였어요. 해 보니 생각보다 어려웠어요. 탭 키를 눌러도 지금 어디에 있는지 보이지 않는 곳이 많았어요. 디자인을 깔끔하게 한다고 포커스 테두리를 지워 버렸던 게 원인이었어요.

## 직접 고쳐 본 것들

### 포커스 표시 되살리기

제일 먼저 포커스 표시를 다시 살렸어요. 무조건 지우는 대신, 키보드로 이동할 때만 또렷하게 보이도록 바꿨어요.

```css
button:focus-visible,
a:focus-visible {
  outline: 3px solid #1d4ed8;
  outline-offset: 2px;
}
```

이렇게 하니 마우스로 클릭할 때는 테두리가 거슬리지 않고, 키보드로 이동할 때는 지금 위치가 분명하게 보였어요.

### 아이콘 버튼에 이름 붙이기

휴지통 아이콘만 있는 삭제 버튼, 연필 아이콘만 있는 수정 버튼이 있었어요. 눈으로 보면 바로 알지만 화면 낭독기는 이름을 읽을 수 없어요. 그래서 버튼마다 접근 가능한 이름을 붙여 줬어요. 화면에는 보이지 않지만 낭독기는 "글 삭제", "글 수정"이라고 읽어 줘요.

### 색만으로 정보를 전달하지 않기

입력 폼에서 잘못된 칸을 빨간 테두리로만 표시하고 있었어요. 색을 구분하기 어려운 사람은 어디가 틀렸는지 알 수 없어요. 그래서 테두리 색과 함께 "이메일 형식이 올바르지 않아요" 같은 문구를 칸 바로 아래에 붙였어요.

## 확인할 때 쓴 체크리스트

스터디에서 받은 체크리스트를 제 상황에 맞게 조금 줄여서 썼어요.

1. 모든 기능을 키보드만으로 쓸 수 있나요?
2. 포커스가 어디 있는지 항상 보이나요?
3. 이미지와 아이콘 버튼에 이름이 있나요?
4. 제목 순서가 건너뛰지 않고 이어지나요?
5. 글자와 배경의 대비가 충분한가요?
6. 오류 메시지가 색 말고 글로도 전달되나요?

### 고치기 전과 후

| 항목 | 고치기 전 | 고친 후 |
| --- | --- | --- |
| 키보드 이동 | 위치를 알 수 없음 | 포커스 테두리가 보임 |
| 아이콘 버튼 | "버튼"으로만 읽힘 | "글 삭제"로 읽힘 |
| 폼 오류 | 빨간 테두리만 | 테두리와 안내 문구 |
| 제목 구조 | 크기만 보고 아무 제목이나 씀 | 순서대로 정리 |

## 오늘 배운 한 가지

오늘 하루를 한 문장으로 정리하면 "보이는 게 전부가 아니다"예요. 눈으로 봤을 때 멀쩡한 화면도 다른 방법으로 쓰면 전혀 다른 경험이 될 수 있어요. 앞으로 화면을 만들 때는 마우스를 내려놓고 한 번, 화면을 끄고 한 번 더 확인해 보는 습관을 들이려고 해요.

### 다음에 더 공부할 것

- 화면 낭독기를 직접 켜고 자주 쓰는 사이트 둘러보기
- 모달 창을 열었을 때 포커스를 어떻게 옮겨야 하는지 알아보기
- 움직이는 효과를 줄이고 싶은 사람을 위한 설정 공부하기

작은 것부터 하나씩 고쳐 나가다 보면, 언젠가는 누구나 편하게 쓸 수 있는 화면을 만들 수 있겠죠. 이번 미션 덕분에 정말 중요한 걸 하나 배웠어요.
